# 播放页屏幕方向与全屏移除验证 — 2026-10-16

## 结果和范围

按用户最终范围，只保留“跟随系统、锁定横屏、锁定竖屏”，不手动旋转视频画面；移除播放页全屏功能。屏幕方向属于播放窗口，System 和 MPV 共用同一窗口控制，不需要给两个播放后端各写旋转实现。

## 实现与接口

新增 `WindowOrientationController`，方向枚举为 `PlayerScreenDirection`：

| 模式 | 主窗口策略 |
| --- | --- |
| `FOLLOW_SYSTEM` / `follow_system` | `AUTO_ROTATION_RESTRICTED`，尊重系统旋转锁定 |
| `LANDSCAPE` / `landscape` | 固定 `LANDSCAPE` |
| `PORTRAIT` / `portrait` | 固定 `PORTRAIT` |

- `set(direction): Promise<PlayerScreenDirection>` 在原生设置完成并回读策略后返回确认值；失败不假装成功，界面显示切换失败，可重新选择。
- 进入播放页时捕获原有方向策略，然后使用跟随系统。`restore(): Promise<void>` 等待已经开始的原生操作结束，再恢复捕获的原策略，重复调用共用同一结果。异常不会通过重复调用变为成功。
- 关闭后的请求被隔离；新播放页等待旧页恢复结算后再捕获窗口策略，避免旧页迟到旋转覆盖新页。返回按钮另有一次性关闭保护，连续点击不会绕过恢复或重复导航。
- 播放页退出通过 `restore()` 恢复策略。切换下一视频沿用同一播放页的方向；重新进入播放页默认跟随系统，不新增全局设置或持久化偏好。
- 移除全屏按钮、状态、覆盖式标题/控制栏、全屏专用参数和文案，以及进入全屏时隐藏系统栏、强制横屏的代码。单击视频不再隐藏控制栏。
- 标题及方向选择固定在顶部；画面、播放控制和状态在正常页面滚动。画面由 ArkUI 按比例布局，高度上限为当前滚动视口的 60%，留出画面外滚动区域，避免视频亮度/音量 pan 手势挡住横屏下的控制区。
- 没有设置视频角度、变换矩阵、MPV `video-rotate`、画面滤镜或旋转元数据；现有适应/裁剪/拉伸设置保留。窗口切换本身不会调用重新打开视频、跳转进度或切换播放后端。

通过可信官方 CLI 操作 API26 x86_64 模拟器中的实际应用，固定系统播放器，复用已保存真实 WebDAV 的六项 H.264 1080p MKV 列表。未修改服务器文件或配置。原始布局和截图保留本机，公开报告不含服务地址、凭据、用户媒体名称或设备标识。

| 实际行为 | 观察结果 |
| --- | --- |
| 点击真实网络第 1/6 项 | 进入竖屏，显示跟随系统，真实画面、1920×1080、播放中 |
| 暂停在约 0:20/47:58，选择锁定横屏 | 窗口由 1256×2760 变为 2760×1256；仍为同一 1/6 项、同一约 0:20，真实画面正向显示，无全屏按钮 |
| 横屏画面外区域向上滑动 | 能滚动到播放、停止、三态循环、上一项/下一项和音量控件；顶部方向和返回仍可见，音量仍为 1 |
| 使用横屏播放按钮播放约两秒后再暂停 | 可操作，返回时间区后为约 0:24；未重开至 0 或更换列表项 |

应用最后停在真实 WebDAV 目录，已退出播放并恢复竖屏。两个真实服务器条目保留。方向策略的原生确认值与物理窗口实际方向是不同概念：上表分别记录 API 确认及布局变化，不将策略设置成功直接等同于所有传感器状态通过。
