## 实现行为

1. `PlaybackPlaylist` 保存条目 ID、媒体源、起始项和完整性标记；复制输入/输出数组，校验索引、空身份、空地址和重复 ID。
2. `LocalPlaybackPlaylist` 消费浏览器当前目录/视频分组的可见排序结果，仅保留已知可用的视频，不另行扫描或递归子目录。点击项失效或不在结果中时返回空结果，不改播第一项。
3. 虚拟条目 ID 与实际播放 URI 分离，同名文件或引用同一源文件的不同虚拟条目不会按名称/播放地址被错误合并。
4. 列表、网格、上下文“打开播放”共用整理路径。完整清单传到播放器页面，显示位置/总数；控制器仍只打开选中的单个源，不自动续播。
5. 保留扫描器的 `snapshotComplete`，贯穿索引回读、目录缓存、控制器和页面。失败后的重投影保留失败；虚拟目录验证/载入失败保留旧数据并显示失败，成功刷新才清除。
6. 不改数据库结构。持久化缓存没有每个范围的完整性证明，冷读时保守标记未确认，界面显示“清单未确认完整”；刷新成功后使用实际扫描标记。

## 保留边界与异常

- 当前系统媒体扫描器本来只查询视频。PNG 已实际导入，但“混合类型由列表构建器排除”的独立覆盖来自 SDK 用例，不能把视频扫描结果冒充混合目录实测；字幕播放仍为 TODO。
- MPV simulator 依赖为明确不支持运行的占位 HAR。没有 MPV 实播/原生队列 PASS。网络列表、正常 EOF 自动下一项、列表循环、失败切项和资源释放验收仍待后续阶段。
- 一次 HDC 回收布局使用 Windows 正斜杠绝对路径失败，改为 Windows 原生路径后成功；媒体库父路径访问被系统拒绝，随后按官方说明使用允许的精确 FUSE 路径导入。均未通过提权或绕过授权处理。
- 原工作区仅对已授权 FFmpeg 输入做窄只读/复制出；未向原工作区发出源码写入、构建、reset/clean/stash 命令。没有穷尽逐字节快照，因此只报告已观察操作。
