# 错误处理规范

## 统一契约

所有需要展示给用户的失败都必须转换为 `AppFailure`，字段含义固定：

| 字段 | 规则 |
| --- | --- |
| `domain` | 只用于归类：输入、网络、播放、文件、存储或系统 |
| `code` | 稳定业务码，发布后不得改变既有码的含义 |
| `title` | 一句话说明发生了什么，不使用“未知错误”等无效描述 |
| `message` | 说明原因或用户可执行的下一步，不展示平台原始异常 |
| `action` | 只能使用统一恢复动作，不允许页面自行解释错误码 |
| `actionLabel` | 与恢复动作一致；没有可执行动作时必须为空 |
| `retryable` | 仅瞬时故障为 `true`，格式不支持和认证失败不得盲目重试 |
| `diagnosticCode` | `业务码/平台码`，用于反馈定位，不含 URL、账号或凭据 |

业务码前缀固定为 `LNK`，第二段表示领域：`INPUT`、`NET`、`PLAY`、`FILE`、`DATA`、`SYS`。新增错误必须先加入 `FailureCode` 与 `FailureCatalog`，再由功能模块使用。

## 分层职责

```text
系统异常 / HTTP 状态 / 协议异常
              │
              ▼
适配层保留原始 code 与安全 detail
              │
              ▼
FailureCatalog 唯一归一化
              │
              ▼
页面只渲染 AppFailure 并派发 RecoveryAction
```

- 页面禁止按数字错误码分支，禁止临时拼接错误文案。
- `SystemPlaybackPort` 只包装 Media Kit 错误，不决定用户文案。
- 网络预检只负责返回 HTTP 状态或 Network Kit 错误，不保存响应正文。
- 协议模块（WebDAV、SMB、SFTP、FTP、NFS）必须把自身错误转换到同一契约；确需新增类别时先扩充目录。
- 日志、诊断码和埋点禁止记录完整 URL、查询参数、Authorization、Cookie、账号、密码和密钥。

## 恢复动作

- `RETRY`：仅用于超时、DNS、连接中断、服务器 5xx 等瞬时故障。
- `EDIT_SOURCE`：用于地址、认证、访问权限和媒体格式问题，返回来源编辑入口。
- `CHOOSE_FILE`：重新调用系统文件选择器。
- `OPEN_SETTINGS`：只有已经实现对应系统设置跳转时才允许使用。
- `NONE`：用户无法在当前界面修复，页面不得显示无效按钮。

## 异步与生命周期

- 每次打开媒体或发起网络检查都分配递增请求 id，迟到结果不得覆盖当前状态。
- 播放器初始化必须有硬超时；释放时必须清理计时器、文件描述符和播放器实例。
- 平台同时通过 Promise 和事件上报错误时，以包含具体错误码的事件为准，不能被泛化异常覆盖。
- 用户修改输入或离开页面时，旧结果立即失效。

## 测试门槛

- 每个新增映射至少覆盖业务码、可重试性、恢复动作和诊断码。
- 网络模块至少覆盖 401、403、404、429、5xx、DNS、连接失败、超时和 TLS。
- 播放模块至少覆盖不支持编码、读取失败、初始化超时、非法状态和未知错误。
- 发布前执行 `scripts/verify.ps1`，并在设备上验证错误卡片与恢复动作。
