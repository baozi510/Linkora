# 锁定横竖类型并允许 180° 翻转 — 2026-10-17

## 结果与实现

用户进一步明确：锁定当前横屏后，手机换到另一侧横屏，画面仍应跟随翻转。锁定的是横竖类型，不是固定朝向。本轮替代此前 `LOCKED` 策略，默认跟随系统、单个锁定/解除按钮和默认全窗布局保留。

基础提交：`4a8dddf3dc88c8306c8dcc9a8ae142d7e32f3349`。候选分支：`codex/linkora-player-axis-lock-v1`，未合入生产分支。开发和首段验证在 10 月 16 日，补完验证及报告在 10 月 17 日；旧报告保留历史行为，不修改旧结果。

| 操作 | 本轮窗口策略 |
| --- | --- |
| 默认 / 解除锁定 | `AUTO_ROTATION_RESTRICTED`，遵从系统旋转开关 |
| 当前为横屏时锁定 | `AUTO_ROTATION_LANDSCAPE`，允许正向/反向横屏，不能变为竖屏 |
| 当前为竖屏时锁定 | `AUTO_ROTATION_PORTRAIT`，允许正向/反向竖屏，不能变为横屏 |

锁定操作在既有串行队列中读取当前全窗 `windowRect`，只识别横竖类型，随后由系统传感器处理 180° 翻转；没有自己旋转画面、推算渲染尺寸或增加传感器监听。窗口尺寸不可用或正方形时拒绝确认，避免猜测横竖类型。锁定状态显示“已锁定，可翻转”。

锁定期间使用原生不受控制中心旋转开关控制的单轴策略，使同轴翻转仍生效；解除后恢复受该开关控制的系统跟随。原生设置确认、错误提示、离页隔离、退出恢复和跨页交接保持不变。
