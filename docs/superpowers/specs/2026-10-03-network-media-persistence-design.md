# 网络媒体持久化与 WebP

用户已授权直接完成，沿用当前会话，不再要求确认。替代上一版128张/24小时临时缓存规则：元数据存现有加密RDB，缩略图放 filesDir/network-media；不按时间、数量自动删除。只接网络视频，本地与串流沿用原流程，代理保留，提取仍可独立停用。

schema v9 新增 network_media_metadata，cache_key 为既有服务器配置/文件版本 SHA256，server_id 外键级联删除，保存 duration_ms/width/height/updated_at。不存凭据或代理地址，不把网络项混进本地媒体表。沿用 LinkoraDatabase 的迁移事务与写队列。

沿用 NetworkMediaCache API（构造时增加serverId），图片字段改名imageData以容纳WebP/JPEG。正常读数据库及持久文件，内存最多24条只限制RAM；不限制持久记录/图片数量，不设期限。写元数据和图片各自失败时仍保留可用数值，缺图仍可重试抽帧，失败30秒抑制重试。安全的单图256KiB读取边界保留；当前固定224×126预览远低于此值。

新缩略图优先系统ImagePacker的image/webp（quality85），不支持时保留JPEG回退。旧cacheDir/network-media中的JSON/JPEG按实际访问迁移到数据库与filesDir，成功后才删除对应旧缓存，不做目录扫描或网络重新读取。迁移允许旧时间戳，不因24小时失效。

文件版本变化使用新键；主动刷新只重新获取目录列表，已有元数据和图片继续使用缓存，不销毁或重写；新增或版本变化的文件按新键获取。删除服务器在写队列内先清理所属图片，成功后才删除服务器并级联删除元数据；清理失败保留归属记录以便重试。这是明确事件清理，不是容量或时间淘汰。保留旧版本图片直至对应服务器删除，符合用户无容量限制要求。系统可清除cacheDir，持久图放filesDir。

提取仍为同一个HAR中fetchMetadata→fetchFrameByTime两步，共用一个AVMetadataExtractor；本轮不新增提取器抽象或拆分UI。两个结果分别存储，元数据不依赖图片是否成功。补取图片的未知数值沿用已知元数据，宽高作为一对更新，包括超时后的部分结果。同一FileMediaPreview用于列表/网格及本地/网络显示。
