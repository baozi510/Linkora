# 本地虚拟文件夹与重复媒体映射设计

> 2026-10-01 规则更新：同一目录内不再重复添加同一原文件 URI，跨虚拟目录仍允许独立引用。界面文案改为“添加视频”“新建文件夹”，创建时说明原文件位置不变。下面允许同目录重复的描述为最初设计，已被此规则取代；历史重复记录保留，不做自动清理。首页固定“本地媒体”入口已实施，用于系统扫描目录；根层手动添加文件仍与用户文件夹同级，不自动归入该入口。

## 目标

在现有本地媒体页面加入应用内虚拟文件夹。用户可以在本地根目录或任意虚拟
文件夹中导入视频、创建子文件夹，并允许同一真实文件被重复添加到同一或不同
虚拟文件夹。系统媒体库目录保持只读，不允许导入或新建文件夹。

本次仅实现当前手机和平板范围，不增加 2in1 设备声明、目录授权、真实目录、
目录导入或文件复制能力。

## 用户交互

- 本地根目录和虚拟文件夹的顶部栏增加“更多”按钮。
- 菜单包含“导入视频”和“新建虚拟文件夹”。
- 系统媒体库目录不显示该按钮，也不提供禁用占位项。
- 根目录导入的视频成为根级虚拟项；在虚拟文件夹中导入的视频归属当前文件夹。
- 新建文件夹使用包含 `TextInput` 的输入弹层。名称去除首尾空白后不能为空；
  同一虚拟父目录内不允许同名，不同层级允许同名。
- 虚拟文件夹在列表和网格中显示“虚拟文件夹”标记，避免与同名系统目录混淆。
- 虚拟文件夹沿用本地页面当前的单实例、无转场目录切换和逐层返回逻辑。
- 长按虚拟文件夹可重命名或删除。删除文件夹会递归删除其子文件夹和虚拟媒体项，
  但不会删除设备中的真实文件。
- 虚拟媒体项沿用媒体菜单；“从列表移除”只删除当前虚拟映射。

## 身份模型

真实文件和虚拟目录项使用不同身份：

- 真实文件由现有 `document_picker` locator 保存，locator 是系统返回的文件 URI。
- 每次导入都创建独立虚拟 locator，类型为 `virtual_entry`，locator 格式为
  `linkora://item/<uuid>`。
- 虚拟文件夹类型为 `virtual_folder`，source key 格式为
  `linkora://folder/<uuid>`。
- 虚拟根目录使用保留 collection key，不作为可见文件夹显示。
- 多个虚拟 locator 可以关联同一个 `media_entity` 和同一个真实 locator；因此同一
  真实文件可以在同一文件夹或不同文件夹重复出现，每个列表项仍有独立选择和删除
  身份。

虚拟 URL 只用于目录组织和 UI 身份。播放、缩略图和元数据读取前必须解析到真实
locator。播放进度、播放历史和最近播放继续使用真实文件身份，因此所有虚拟映射
共享一份进度。

## 数据存储

复用现有数据库结构，不新增平行目录表：

- `media_entity` 保存共享的媒体元数据。
- `media_locator` 同时保存真实 `document_picker` locator 和独立的
  `virtual_entry` locator；二者通过相同 `media_id` 关联。
- `media_collection` 保存虚拟根和虚拟文件夹，使用 `parent_key` 表达层级，
  `is_virtual = 1`。
- `collection_membership` 将虚拟 locator 放入虚拟根或指定虚拟文件夹。现有
  `(collection_id, locator_id)` 主键不会阻止重复真实文件，因为每次导入都会创建
  不同的虚拟 locator。
- `display_order` 继续表示虚拟项的添加顺序。

数据库升级为 schema v8。迁移将现有“手动添加”集合里的每个真实 locator 转换为
一个根级虚拟 locator，并保留真实 locator、元数据、权限和播放状态。迁移必须可重入，
升级失败时不得删除旧记录。

## 业务边界

本地目录路由根据 URI 命名空间区分来源：

- 空 URI：本地根目录。
- 系统媒体 URI：只读系统目录。
- `linkora://folder/`：虚拟文件夹。

根目录投影合并系统顶层目录、虚拟顶层目录和根级虚拟媒体项。进入系统目录仍由
现有媒体库扫描和缓存负责；进入虚拟目录只查询本地数据库，不触发系统媒体扫描。

导入流程保持使用 `DocumentViewPicker` 与现有持久读取授权。选择完成后先确保真实
locator 和媒体元数据存在，再为每个选择结果创建新的虚拟 locator 与 membership。
即使真实 locator 已存在，也必须创建新的虚拟 locator。取消选择不产生任何记录；
同批数据库写入使用事务，失败时不留下半批记录。

删除虚拟项时先删除其 membership 和虚拟 locator。仅当同一真实 locator 已无任何
虚拟映射时，才删除手动来源记录并撤销其持久读取权限。播放进度可以保留，重新导入
同一真实 URI 后继续共享。

## 组件与接口

- `LibraryPage` 根据当前目录类型决定是否显示顶部菜单，并承载新建文件夹输入弹层。
- `Index` 继续负责把页面事件转发给 `LibraryFeatureController`。
- `LibraryFeatureController` 增加虚拟目录加载、创建、重命名、删除和定向导入操作，
  并保持当前单一业务状态投影。
- 扩展现有 `ManualMediaRepository` 与 `ManualMediaStore`，由它们继续统一负责手动来源、
  虚拟目录和虚拟映射；文件选择和真实媒体元数据仍复用
  `HarmonyLocalFilePickerGateway`、`LocalMediaPicker` 与现有读取器。
- `LocalMediaFolder` 和 `LocalMediaAsset` 增加足够的来源/目标信息，使 UI 能区分
  系统项与虚拟项，并让虚拟项解析出真实 `MediaSource`。不创建第二套页面组件。

## 错误处理

- 同级重名、空名称和数据库失败在输入弹层附近反馈，不改变当前目录内容。
- Picker 取消视为无操作；Picker 或权限失败继续使用现有本地文件错误提示。
- 真实 URI 权限失效时保留虚拟项并标记不可用，允许用户重新选择授权或从列表移除。
- 删除虚拟文件夹使用确认对话框，并明确说明真实文件不会被删除。

## 2in1 后续边界

本次不修改 `module.json5` 的设备类型，不实现 2in1 目录选择或真实目录创建。未来只有
在运行时确认 `SystemCapability.FileManagement.UserFileService.FolderSelection` 和相应
读写授权可用时，才显示目录导入或真实目录绑定入口。现有 `media_collection.locator`
可用于保存未来的真实目录 URI，无需本次预留新字段。

## 测试与验收

- 数据库 v7 到 v8 迁移保留现有手动添加媒体并生成根级虚拟 URL。
- 同一真实 URI 连续导入两次生成两个不同虚拟 URL，并共享真实目标和播放进度键。
- 根目录和虚拟目录允许导入、新建；系统目录不显示相关菜单。
- 虚拟文件夹支持多层进入、逐层返回、同级重名校验和跨层同名。
- 删除单个映射不影响其他映射；递归删除文件夹不删除真实文件；最后一个映射删除后
  正确清理持久授权。
- 列表/网格、长按高亮、缩略图、排序、过滤、刷新和现有系统目录浏览没有回归。
- 单元测试、V2 静态守卫以及 Debug/Release HAR、HAP 构建全部通过。
