# 网络列表正式媒体提取接入

用户要求直接完成，明确免除设计/计划确认；沿用当前会话执行。只改网络视频，本地已有流程继续使用。代理模块保留；提取装配可单独停用，无设置项。

显示复用 FileMediaPreview。列表保留大小、年月日日期，补实际分辨率和缩略图角落的时长；网格无 chip，只有缩略图和标题。非视频和文件夹不提取，文件夹只显示日期。未知信息不伪装为真实时长。

仅可见预览请求提取，单个浏览器串行处理一个视频，相同文件合并请求。滚出视口、切换目录、离页、开始播放时取消对应任务；旧结果不得更新新目录。总提取期限8秒（包括连接和代理建立），取消返回与实际资源退出分别处理，清理完成前不开始下一任务。

entry 独立 NetworkMediaLoader 负责协议→代理→HAR，NetworkMediaCache 负责可丢弃缓存；UI 不依赖 HAR 类型。SMB/SFTP/FTP/NFS/WebDAV 使用已有代理读取，不改变播放流程和串流页。严格 SFTP 不能绕过指纹校验；普通服务器表单补受信任 SHA256 指纹传递，缺失/错误时保留基础显示。

缓存键复用 SourceIdentity SHA256，包含服务器id/config revision/协议、完整路径、大小和修改时间；不持久化凭据和代理URL。缓存使用独立 cacheDir/network-media 目录、JSON数值及JPEG，128条，每张最多256KiB，24小时期限；内存24条、失败30秒避免连续重试。部分元数据有效仍显示；无图部分结果只在内存短期保留。目录强制刷新使当前文件缓存失效。图片每个消费者独立解码并释放，HAR返回图像在编码后释放。缓存异常回退正常提取或图标，不影响目录与数据库。

停用只改 LinkoraFeatures 的一个编译期常量/工厂返回null，缓存与提取均不读取，基础列表和proxy继续可用。实际移除时删除loader/cache、HAR依赖与factory导入、内部测试相关连接；保留proxy和HttpRemoteReadSession。没有新增数据库表、框架或产品依赖。

验证：真实ETS的Node/TypeScript检查覆盖串行/合并/取消/迟到/故障/缓存失效/边界；原123项单元、持久化及Debug/Release构建；模拟器实际列表/网格、滚动/离页、缓存重启、模块停用后基础列表，原媒体16场景回归。设备API26；API20接口使用不等于真机验证。
