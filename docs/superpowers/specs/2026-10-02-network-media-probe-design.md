# 网络媒体信息与缩略图实验模块

日期：2026-10-02。状态：设计及计划已确认并实现。用户在设备测试后追加确认：鉴权 WebDAV 也经代理。

## 目标与已确认范围

用户已确认：先完成代理，再做独立、方便装卸的媒体信息与缩略图模块；不添加设置选项；这一阶段先做模块和模拟器内部测试，暂不接入文件列表，也不在播放前自动执行。

成功标准是系统能从真实网络视频读出与本地相同含义的时长、视频宽高及一张预览帧，并且取消、失败或移除实验模块后，基础目录信息和已有播放仍然可用。

采用已有 API20 能力，不打包 FFmpeg，不实现 API12 分支，不使用 API26 新增的提取超时接口。本次设备证据仍来自 API26 模拟器，不能据此声称已在 API20 实机验证。

## 现有代码与技术依据

- `LocalMediaMetadataReader` 用系统 AVMetadataExtractor 读取时长和宽高，文件大小和日期来自 stat。
- `LocalMediaThumbnailLoader` 使用媒体库缩略图服务，不能把网络 URL 当成媒体库 URI。保留此本地流程。
- 串流页已有 `NetworkMediaMetadataReader`，通过 setUrlSource 读取点播信息。本轮保留串流页既有行为，不顺带迁移其代码。
- `linkora_proxy` 已提供短期 loopback URL。SMB/SFTP/FTP/NFS 的打开和鉴权由 entry 服务负责；WebDAV 的 URL 和 HTTP Basic 鉴权由现有服务负责；本次系统未转发 headers，鉴权来源改经代理。
- 网络目录条目已有名称、路径、类型、大小和完整修改时间戳。这些是基础层数据，不放进实验 HAR，不用增强提取的失败覆盖它们。

系统 API20 的 AVMetadataExtractor 支持 setUrlSource(url, headers)、fetchMetadata 和 fetchFrameByTime；网络抽帧无需另建 AVImageGenerator。支持范围遵循系统接口，不能将 MP4/MPEG-TS/MKV 的点播能力推广到所有容器、直播或 HLS/DASH。

依据：[华为网络视频缩略图指南](https://developer.huawei.com/consumer/cn/doc/doccenter-capabilities/video-thumbnail-system)、[OpenHarmony AVMetadataExtractor 接口](https://raw.githubusercontent.com/openharmony/docs/master/zh-cn/application-dev/reference/apis-media-kit/arkts-apis-media-AVMetadataExtractor.md)、本机 Media Kit SDK 声明。

## 方案选择

推荐新增小型 HAR `linkora_media_probe`，只接收 HTTP/HTTPS 地址及可选请求头，使用一次系统提取实例完成信息和抽帧。entry 负责准备来源、持有并释放代理租约。HAR 不依赖协议客户端、代理 HAR、数据库或页面，单独移除时不影响代理模块。

另一种做法是把协议打开和代理生命周期一起放入提取 HAR；这会把两个实验模块绑在一起，鉴权及装卸边界变复杂。只扩展 entry 现有串流 helper 则无法满足独立 HAR 的装卸目标。因此选择第一种。

## 输入、输出与所有权

HAR 导出 `NetworkMediaProbe` 和结果类型：

- `inspect(url, headers)`：一次明确调用读取一个网络视频。输入仅 HTTP/HTTPS；验证地址、请求头和长度，不把账号密码拼进 URL。不向日志输出地址、请求头、令牌或系统原始错误消息。
- 输出：`durationMs`、`width`、`height`、`metadataComplete`、`thumbnail`、有限状态和数值错误码。数值只接受有限的正数，缺失或非法值为零；时长保持毫秒，与本地一致。
- 状态为完成、仅信息成功、不可提取、已取消或超时。格式不支持或抽帧失败只表示增强信息不可用，不表示原文件已失效。
- `thumbnail` 为可空 PixelMap。成功返回后归调用方所有，由调用方释放；HAR 不缓存、共享或再释放已交付的 PixelMap。
- `cancel()` 使当前任务失效并启动系统实例清理；`close()` 等待已启动的创建/提取/清理退出，重复调用安全。关闭后的实例不能再发起提取。

每个实例仅允许一个活跃任务。活跃时再次 inspect 明确拒绝，避免暗中取消另一调用者及制造无上限后台任务。正常结束后可继续提取下一个来源。

## 提取与取消流程

1. 创建 AVMetadataExtractor，检查当前任务是否仍有效。
2. setUrlSource 设置来源及请求头，先 fetchMetadata。
3. 信息成功后再 fetchFrameByTime。目标尺寸 224×126，与共用预览的 16:9 比例一致；使用最近关键帧。已知时长时选一秒附近且不越过末尾，未知时长选零。
4. 抽帧失败保留已读出的媒体信息；信息失败不继续抽帧。
5. 整次 inspect 从创建开始使用八秒调用截止时间，覆盖信息和抽帧，不给每个步骤重新计算八秒。到期及时返回已获得的部分信息及超时状态，并开始清理。
6. 取消、关闭、异常和迟到结果均按同一任务标识检查；迟到的实例或 PixelMap 必须释放，不能交付给已取消调用。
7. 系统实例只释放一次。调用方返回超时与系统原生工作真正退出分开记录；close 的实际完成时间需要设备验证，不能把 Promise.race 返回当作资源已经释放。

模块不实现整文件下载或视频落盘缓存。系统解析器可能读取多个范围；内部测试统计真实读取次数和字节量，不预先宣称固定只读文件头或完全不会读完小文件。

## 来源装配

- SMB/SFTP/FTP/NFS：内部测试通过 NetworkDirectoryService.openReader 获取只读会话，调用代理 buildProxyUrl，再把 lease.url 传给提取 HAR。
- SFTP 严格模式继续使用可信指纹，缺失或不匹配时拒绝；不降低现有校验。
- WebDAV：用户在 API26 实测发现系统请求头丢失后确认改经代理。entry 的 HttpRemoteReadSession 使用 fileUrl 和现有 basicAuthorization 发出有界 HTTP Range 请求，再交由代理；不重复认证编码，不回退整文件下载。
- 普通 HTTP/HTTPS 点播：直接传入地址。HTTP 串流页本轮没有任何新增调用；HLS/DASH 和直播不作为这一实验的成功样本。
- 代理所有权始终在调用方。取消时先让 probe 失效，再撤销租约以中断在途 loopback 读取，最后等待 probe 与 proxy 的关闭完成。正常完成后释放提取实例和租约。

`LinkoraFeatures` 仅提供模块装配入口。内部测试由专用 Debug Want 参数启动；普通启动不创建提取实例或代理。Release 不启用该测试入口，不增加设置页面或新的应用导航。

## 缓存、基础信息与移除

这一阶段没有批量调度、磁盘缩略图缓存、增强信息数据库、自动扫描或列表请求。内部测试临时写出的缩略图仅用于验证和导出，验证后清理。

关闭或移除提取 HAR 后，NetworkDirectoryEntry 原有名称、大小、修改时间和类型图标继续可用。本地数据库、虚拟目录、目录列表、现有渐进下载播放及串流页保持原实现。

移除提取 HAR 的步骤应写在模块 README：去掉 LinkoraFeatures 装配、专用 Debug 测试导入/调用、对应测试、root 模块配置及 entry 包依赖。无需删除代理 HAR、协议读取适配或基础目录模型。须在独立测试工作树实际构建移除后的应用。

## 验证与交付

1. 单元验证有限数值转换、信息成功但抽帧失败的部分结果、创建期间取消、迟到 PixelMap 释放、重复关闭和单任务限制。测试使用系统调用替身，不冒充真实设备证据。
2. 模拟器以已知时长和分辨率的视频为参照，分别验证 SMB、SFTP、FTP、NFS 代理来源以及普通 HTTP、需要鉴权的 WebDAV 直连来源。记录真实输出及读取量，与参考信息比较。
3. 把实际 PixelMap 导出为小图，检查图片尺寸、可解码且含有效画面；视觉查看导出的图，不能只检查对象非空。区分系统返回尺寸与请求尺寸。
4. 使用尾部含索引的视频、短视频和格式不支持样本验证 seek、时间点边界和失败回退；不增加第三方解码器弥补系统不支持的格式。
5. 可控延迟端点确认系统已请求数据后再取消，验证及时返回、迟到结果清理、租约撤销、关闭退出和后续任务可继续。失败结果不得包含凭据或令牌。
6. core/proxy/提取 HAR 和应用 Debug/Release 构建通过，已有单元及本地持久化回归通过。移除新 HAR 后基础应用构建与普通启动通过，串流页既有行为回归通过。
7. 结果、模拟器输出和缩略图证据写入 Git 忽略的 artifacts；测试结束恢复普通应用启动，删除临时配置/媒体缓存并关闭本次创建的测试服务。

以上通过后再另行确定列表的按需提取、缓存和展示方案，不将内部实验成功等同于已完成列表接入。

## 2026-10-03：分阶段获取与计时

在现有 HAR 内增加 BOTH / METADATA / THUMBNAIL 三种获取方式，默认 BOTH 保持原调用兼容。元数据专用调用不抽帧；缩略图专用调用不读取元数据，可使用已缓存时长限定取帧点。BOTH 使用同一提取器，元数据成功后先回调并发起落库，再抽帧和编码。生产列表缺少图片且已有有效元数据时只补图片。

显示时机按用户后续要求更新：生产页面不使用中间回调展示，等待元数据与图像处理结束后统一交付；默认先显示大小和修改日期。缓存命中也等解码完成，只缓存元数据或缓存图片损坏时保持基础信息，待补图请求结束后再交付。失败/超时沿用已有部分信息回退；取消/离页不显示迟到结果。

返回独立的准备、元数据、抽帧、总耗时，使用系统单调时钟；未执行阶段为 null，取消/失败阶段记录已耗时间，结果是快照，迟到清理不修改结果。连接准备、WebP/JPEG 编码在内部设备证据另计。缓存命中不冒充提取测量；不改数据库结构、缓存有效期、可见区域调度、串流或代理装配。
