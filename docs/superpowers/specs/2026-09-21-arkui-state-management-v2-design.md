# ArkUI 状态管理 V2 全量迁移设计

## 目标

将 `entry/src/main/ets` 中现存的 37 个 `@Component` 组件与页面迁移为
`@ComponentV2`，使应用 UI 只使用状态管理 V2。现有 2 个 V2 列表组件继续保留，
界面行为、导航层级、刷新、虚拟滚动和播放器行为不得改变。

## 迁移规则

- 组件内部响应式状态：`@State` 改为 `@Local`。
- 父组件输入：`@Prop` 改为 `@Param`；只在初始化时读取的输入才使用
  `@Param @Once`。
- 组件输出回调：函数属性改为 `@Event`，普通私有方法保持不变。
- 状态监听：`@Watch` 改为 `@Monitor`，保持原触发语义；仅在确有深层属性
  变更时才迁移相应数据类为 `@ObservedV2/@Trace`。
- 主题色：入口组件使用 `@Provider('linkoraAccentColor')`，后代组件使用
  `@Consumer('linkoraAccentColor')`，删除 V1 的 `AppStorage/@StorageProp` 通道。
- 内置组件双向绑定：将 V1 的 `$$` 改为 V2 的 `!!`。
- `@BuilderParam`、生命周期和 ArkUI 原生组件保持原结构，除非编译器要求按 V2
  语法调整。

## 实施顺序

1. 迁移无内部状态的叶子组件与共享控件。
2. 迁移本地、网络、设置、历史等页面及其状态监听。
3. 迁移播放器组件与入口 `Index`，同时切换主题色 Provider/Consumer。
4. 删除全部 V1 装饰器、旧主题状态代码、无引用导入和确认无调用者的文件。

每一层迁移后都执行编译检查，避免一次性机械替换掩盖父子数据流错误。

## 数据流与兼容性

父组件继续持有业务状态，子组件通过 `@Param` 接收，通过 `@Event` 回传动作。
现有 service、store、model 和 `linkora_core` 不因本次迁移改造；只有编译或设备验证
证明某个对象依赖深层响应式更新时，才给该对象增加 V2 可观察标记。

项目最低兼容 API 为 12，满足 `@ComponentV2`、`@Local/@Param/@Event` 和 `!!`
的最低版本要求。

## 清理边界

- `entry/src/main/ets` 中不再保留 `@Component`、`@State`、`@Prop`、`@Watch`、
  `@StorageProp` 或 `$$`。
- 不引入兼容包装层，不为未来需求新增状态容器。
- 不改业务逻辑，不顺带重命名页面或重排 UI。
- 仅删除经全仓引用检查确认无调用者的代码。

## 验收

- 静态扫描确认 UI 源码没有 V1 状态管理装饰器或旧双向绑定。
- Hvigor 单元测试通过，Debug HAP 构建通过。
- 安装到设备后验证：应用启动、主题切换、本地与网络列表/网格切换、目录导航、
  下拉刷新、长按菜单、设置保存、播放器进入/退出和系统返回。
- 对比迁移前后关键页面截图，确保没有布局或样式回归。
