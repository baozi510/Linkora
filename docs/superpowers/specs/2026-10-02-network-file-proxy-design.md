# 网络文件代理实验模块

日期：2026-10-02。阶段：待审阅的设计，不代表已经实现或验证。

## 已确认的目标

- HTTP/HTTPS 串流保持直连，不做代理。
- 先实现并验证网络文件代理，再另做媒体信息与缩略图模块。
- 实验能力通过开发装配接入和移除，不增加设置开关或插件管理页面。
- 移除实验能力后，网络文件仍有名称、文件类型、大小、修改日期这些基础信息；未知值保持未知，不伪造。
- 最低 API 20；保留已有兼容路径，本次不验证 API 12–19。

## 当前代码与缺口

`NetworkDirectoryService` 已经提供各协议的目录基础信息。WebDAV 有 HTTP 文件地址；SMB、SFTP、FTP、NFS 只暴露列表和下载方法，播放使用渐进下载缓存。

`linkora_core` 已有 `RemoteReadSession` 的 size/read/cancel/close 契约，但实际浏览服务尚未实现它。现有 C++ 库可复用：SMB 的 pread、SFTP 的 seek/read、NFS 的 pread，以及 FTP 的 REST/RETR。

已有 `NetworkMediaMetadataReader` 用于串流测试链接；它不承担本次代理服务，也不在本阶段扩展为缩略图模块。

## 方案选择

推荐：独立 `linkora_proxy` HAR 实现本机 HTTP 服务；entry 中的协议适配器提供 `RemoteReadSession`。代理不认识服务器账号、具体协议或页面，后续媒体提取模块只消费地址与释放句柄。

另两个方案：在 entry 内做普通服务，改动较少但移除边界较弱；把 HTTP 服务和四种协议全部搬到新的 C++ 模块，装配集中但需要迁移和重复维护现有协议实现。采用第一种，复用现有协议库。

## 模块边界和接入

- `linkora_core`：复用已有随机读取契约，保持不依赖 HarmonyOS Kit。
- `linkora_proxy`：只依赖 core 和系统 NetworkKit；负责 HTTP 请求、字节范围、令牌映射和生命周期。
- entry 协议服务及对应 native 库：增加打开只读会话、取得实际文件大小、随机读取、取消和关闭能力。原列表/下载方法保留。
- `LinkoraFeatures`：唯一装配点，负责创建代理并传入读取会话；页面不创建监听器。

公开方法约定：异步 `buildProxyUrl(reader, contentType)` 返回一个短期句柄，包含 `url` 和幂等 `release()`；模块另有幂等 `close()`。返回 Promise 是因为需要实际启动监听和注册会话。注册失败时关闭传入会话，成功后由句柄接管会话所有权。

代理采用 `127.0.0.1` 和系统分配端口；URL 只含随机不可预测令牌，不含远程路径或凭据。句柄只在本次进程内有效，不写入数据库、最近播放或书签；这些功能继续保存原始来源身份。

独立 HAR 是代码和构建层面的可移除模块，不是用户可下载的动态插件。移除时取消装配、依赖和模块构建项；core 与网络目录基础信息不依赖此 HAR。协议读取接口可以保留给其他消费者。

WebDAV 本阶段保持其现有 HTTP 文件直连；它不需要为了统一外形绕进本机代理。后续媒体读取模块会接受直连地址或代理句柄两种来源。

## 读取和 HTTP 行为

- 原生网络操作在异步工作线程执行；同一读取会话串行操作，不在 UI 线程等待网络，也不在多个 native 工作线程里阻塞争抢同一会话锁。
- 打开会话时用远端 stat 获取真实大小，不能完全信任缓存列表中的大小。偏移和大小须为可精确表示的非负整数，超出范围明确失败。
- 每次读取和发送最多 256 KiB，等待发送完成后再读下一块。不建立整文件缓存，不为取信息主动顺序下载整个视频；消费者请求整文件时仍可以按块输出。
- 支持 GET、HEAD。HEAD 返回真实 Content-Length、Accept-Ranges、Content-Type，不读取文件正文。
- GET 无 Range 返回 200；支持 `bytes=start-end`、`bytes=start-`、`bytes=-suffix`，返回 206 和准确的 Content-Range/Content-Length；超过文件末尾的 end 截到末尾。
- 合法但无法满足的单范围返回 416 和 `Content-Range: bytes */size`。不支持 multipart；多范围或未知单位按忽略 Range、返回 200 处理，不伪造部分响应。
- 空文件无范围请求返回长度为零的 200，有字节范围请求返回 416。非 GET/HEAD 返回 405；无效令牌返回 404。
- TCP 头部可能分多次到达，累计到完整头部后才解析；头部限制 16 KiB、读取头部超时 8 秒。第一版每条连接只处理一个请求并返回 `Connection: close`，不实现 keep-alive、请求管线或上传。
- 相同文件的并发请求共享会话并串行读，限制活跃句柄最多 8 个、客户端连接最多 16 个；超额明确拒绝，避免无上限队列和内存增长。

HTTP 范围语义参考 RFC 9110，第 14 节：https://www.rfc-editor.org/rfc/rfc9110.html#section-14 。系统 TCP 服务使用 SDK 中的 `constructTCPSocketServerInstance`、`listen`、`getLocalAddress` 和连接 `send/close`。

## 协议适配与失败策略

- SMB：复用 libsmb2 的只读打开、stat、pread 和现有认证参数。
- SFTP：复用 libssh2 的认证/主机身份校验；seek64 后按块读取。不得为实验放宽安全策略；严格校验缺少所需指纹时明确失败。
- NFS：复用现有版本与连接选项，stat 后使用 pread。
- FTP：复用现有被动模式、TYPE I、SIZE、REST 和 RETR；范围完成后正确关闭数据连接并结束或重建传输状态。服务器不支持恢复读取时明确失败，不冒充随机读取。现有未支持的 FTPS、主动模式不在本次补齐。
- 新增边界验证路径、偏移、长度和 FTP 命令参数，拒绝 CR/LF 注入；不把凭据或令牌写入日志。
- 网络失败在发送响应头前转成受控失败响应；发送头后失败则关闭连接，不把截断正文当成成功。
- 所有远程操作必须有超时与取消路径，包括连接建立。取消使后续读取立即失效；资源销毁等待在途原生操作退出，禁止提前释放仍被读取的连接或文件句柄。
- 句柄 release 先撤销令牌，再关闭关联客户端和远程会话。模块 close 还须关闭现有客户端；关闭监听器本身不足以关闭已连接客户端。

## 本阶段范围

交付代理 HAR、四种协议的随机读取适配、开发装配入口和可运行验证。先通过内部测试入口验证，不把所有现有播放链路直接切换到代理。串流页、本地列表、目录基本信息和数据库 schema 不因本阶段改变。

时长、分辨率、视频缩略图、增强信息缓存、批量提取调度属于下一阶段。代理验证完成之前不开发这些能力。

## 验收

1. 独立 HAR 及应用 Debug/Release 构建通过；去掉代理装配与构建依赖后基础应用仍可构建。
2. 运行范围解析检查，覆盖闭合/开放/后缀范围、越界、空文件、非法数字、多范围和大文件偏移。
3. 在模拟器启动真正的本机代理，通过 HTTP 验证 HEAD、文件头/尾/中间范围及状态码，将结果与原文件字节对比。
4. 对 SMB、SFTP、FTP、NFS 分别验证真实随机读取与 HTTP 输出；没有可用测试端点时明确记录未验证的协议，不能仅凭构建宣称其稳定。
5. 模拟器验证请求取消、读取中释放、模块关闭、重建实例、错误凭据、文件失效、超额请求，确认无崩溃、无旧令牌继续访问和无持续读取。
6. 模拟器操作回归现有网络目录与播放、HTTP 串流直连，确认实验模块未装配时基础信息和既有功能仍可用。

只有以上证据满足后，才进入下一阶段的媒体信息和缩略图设计与实现。
