# 本地媒体库

## 范围

Linkora 的本地入口分为两条互不替代的路径：

- “选择本地视频”使用系统 `DocumentViewPicker`，只获得用户主动选择文件的访问能力。
- “本机媒体”使用 `PhotoAccessHelper` 查询系统已经索引的图片和视频，首次使用时请求 `ohos.permission.READ_IMAGEVIDEO`。

应用不遍历系统私有目录，不申请写入媒体库权限，也不会在扫描时修改或上传文件。

## 模块边界

```text
LibraryPage
    │  browse-mode / album / play intent
    ▼
LibraryFeatureController
    │ LocalMediaScanOptions
    ▼
MediaLibraryGateway                 LocalFilePickerGateway
    ├── LocalMediaPermission            └── LocalMediaPicker
    ├── LocalMediaIndexStore → SQLite 缓存快照
    └── LocalMediaScanner
             │
             ▼
       PhotoAccessHelper
          ├── Assets → 图片与视频的完整源快照
          ├── Albums → 相册元数据索引
          └── Album.getAssets() → 相册首次进入时按需读取
                         │
                         └── MediaSource → PlaybackEngine

ManualMediaRepository → SQLite 手动来源集合
LocalMediaProgressRepository → SQLite 播放进度投影
```

- `LocalMediaPermission` 负责已有授权检查与用户授权请求，结果通过明确对象返回。
- `LocalMediaScanner` 始终获取图片与视频的完整源快照，读取相册元数据、按需读取单个相册，并处理分页、系统对象释放和异常归一化。视频模式不会生成另一份可清理图片的局部快照。
- `LocalMediaCatalog` 是与 ArkUI 和系统 API 无关的纯核心模块：以稳定 URI 去重并生成页面投影，不负责访问媒体库。
- `LibraryFeatureController` 启动时先发布数据库中的最后一份完整快照，再用媒体总数、最新资产和相册摘要组成的轻量指纹判断是否需要校准；模式、筛选和视图切换只做内存投影。相册首次进入时先展示数据库成员，再向系统媒体库校准并按 `albumUri` 保留进程内缓存，重复进入不再访问系统媒体库。
- `LocalMediaAsset` 保存展示所需的 URI、文件名、类型、时长、尺寸、大小和修改时间；字幕条目不可触发播放。
- `ManualMediaRepository` 保存系统文件选择器授予的 URI 和真实文件类型，并按 6 小时有效期校验可读性；元数据解析在数据库事务外以有限并发执行，解析失败只更新文件级信息，不会把已知时长和分辨率清零。失效授权保留为可识别、不可播放的条目，不静默丢失。
- `LocalMediaProgressRepository` 将 `playback_state` 批量投影为列表进度，不把播放状态塞进静态媒体元数据。
- `LocalMediaFolder` 是与系统 `Album` 解耦的只读相册快照，保存名称、资源总数、视频数、图片数和封面 URI；该历史类型名后续可独立迁移，不影响页面语义。
- `LocalMediaScanOptions` 统一传递浏览模式、当前相册、相册筛选、查询批大小和文件后缀策略；UI 不构造系统查询条件。`maxResults` 当前作为每批大小，不是列表总数上限。
- `LibraryPage` 只渲染扫描状态、搜索结果并发送播放意图，不直接依赖系统媒体库 API。
- `SystemPlaybackPort` 继续统一通过只读文件描述符播放本地 URI。

## 状态约定

```text
idle → scanning → ready
             ├→ empty
             ├→ permission_denied
             └→ failed
```

重复刷新在 `scanning` 或后台同步状态下被忽略。权限已经授予时，应用下次启动先展示缓存；缓存指纹变化、指纹读取失败或距上次完整扫描超过 6 小时时才执行全量校准。刷新期间保留现有列表，失败时继续显示旧快照并提供错误提示。数据库写入失败时继续展示当次扫描结果，同时明确提示索引未保存。扫描代次和最近完成时间保留在核心状态中；新旧内容相同时不替换列表数据引用。未授权时不会在启动阶段主动弹窗。

列表使用 ArkUI 系统 `Refresh` 组件提供下拉刷新，不在工具栏重复放置刷新按钮。下拉跟随比例被压低到仅用于系统手势判定，列表视觉位置保持稳定，顶部以悬浮进度图标反馈刷新。首次安装或没有完整缓存时继续使用初始扫描状态；已有缓存时下拉刷新和启动校准都不遮挡列表。

## 相册筛选

本地媒体库提供三种互斥模式，并持久化用户最近一次选择：

- `ALL`：显示系统媒体库返回的全部可浏览相册，包括空相册和仅含图片的相册。
- `NON_EMPTY`：隐藏资源总数为 0 的相册，仍可显示仅含图片的非空相册。
- `VIDEO_ONLY`：只显示 `videoCount > 0` 的相册，作为播放器的默认模式。

“视频模式”从完整源快照中投影去重后的视频扁平列表。“相册模式”根层展示系统用户相册与来源相册，只有 `owner_album_id` 明确表示根归属的文件才与相册并列；相册首次进入时通过 `Album.getAssets()` 获取权威成员列表。未匹配的归属 ID 保留在视频模式，但不得在相册根层冒充根文件。

API 23 及以上同时读取 `USER_GENERIC` 用户相册和 `SOURCE_GENERIC` 来源相册；API 22 可读取 `owner_album_id` 并区分用户相册与根层资产；API 12–21 保留用户相册查询作为保守兼容回退。空名称、点号开头的内部相册以及媒体根相册不作为普通相册卡片展示。

## 当前限制

- 系统资产与相册成员按修改时间倒序分批读取，默认每批 500 条；扫描前后指纹不一致时将结果标记为不完整，不执行过期数据清理。
- 相册列表同时读取用户相册和鸿蒙 API 23+ 的 `AlbumType.SOURCE` 应用创建型相册；所有可浏览相册都交给上层筛选，应用不擅自隐藏来源。
- 系统媒体库视频通过 `PhotoAsset.getThumbnail()` 按可见区域加载缩略图，离开可见区域后释放组件独占的 `PixelMap`。加载器保存最多 24 份原始像素缓存并合并同一 URI 的并发请求；失败结果短暂缓存，避免滚动时重复查询。手动文件选择器返回的单文件授权 URI 暂不生成媒体库缩略图。
- 模拟器已验证权限、自动刷新、非空相册、相册内隔离和视频模式平铺；外部存储、云端占位视频和授权撤回必须在真机继续验证。
- 这里的“相册”是系统媒体库 `Album`，不是对共享存储的无权限递归遍历。任意目录递归扫描需要另建“用户授权目录”功能，不能扩大当前权限边界。

## 浏览模式与文件类型

- 视频模式：聚合符合视频后缀策略的全部视频，以稳定 URI 去重后平铺展示；字幕不作为独立视频卡片出现。
- 相册模式：根层列出可浏览相册和明确的根层文件；若没有根层文件，就只显示相册，不回退显示全部视频。进入相册后只显示该相册资产。
- 右上角 `+` 使用系统 `DocumentViewPicker`，单次最多选择 500 个符合当前视频后缀设置的文件（系统多选上限）。选择结果保存为独立的“手动添加”来源集合，不复制文件，也不将单文件授权伪装成目录授权。
- `+` 只在相册根层出现。手动文件在相册模式根层与相册混合展示，在视频模式与媒体库视频按 URI 去重；相册模式保留不同来源关系，不做跨来源去重。选择后会请求系统文件持久化读权限；若设备/文件提供方不允许持久化，当前会话仍可播放，下一次启动会通过校验明确显示失效。
- 启动时只验证超过 6 小时未检查的手动 URI。失效条目置灰并禁止播放；长按手动条目可以重新选择、移除单条或清理全部失效记录，操作会删除 Linkora 索引并撤销对应的持久化读取授权，不删除原文件。
- 已保存书签的视频会在缩略图底部显示细进度条；退出播放器后重新读取数据库进度。同一 URI 从媒体库和手动来源出现时复用同一播放进度。
- 图库适配器只能提供系统视频资产与用户相册，不等同于真实文件系统目录；相册路径在界面中统一标记为“媒体库”。
- 字幕属于普通文档，不能通过 `PhotoAccessHelper` 自动发现。字幕扫描只适用于应用已获授权的文档、应用沙箱、网络位置或未来可用的目录授权来源。
- 视频和字幕后缀由核心层 `LocalFileFilter` 分类，默认值随 `AppSettings` 持久化；UI、设置和各来源适配器不得各自维护后缀常量。

## 未来目录授权

系统媒体库与物理目录属于不同来源。未来若手机开放持久化目录授权，将新增独立的 `DirectorySource`：它负责目录授权、递归枚举和真实父子关系；现有 Media Library 适配器继续只负责系统资产与媒体相册。两者最终只在核心 Repository 聚合为可播放媒体条目，不允许用目录规则解释相册，也不允许用相册规则裁剪目录树。
