# 网络原生播放列表接入与真实 WebDAV 验证 — 2026-10-16

## 结论与范围

网络目录列表现在实际交给播放器的原生队列，应用显示确认后的当前项、上一项、下一项与选择列表。真实 WebDAV 的两个 H.264 目录（6 项、20 项）通过下面列出的系统播放器操作检查。另一个 22 项 4K/60fps H.265 目录发生打开超时，原因未确认，保留失败；本轮不是所有格式或全部后端验收通过。

## 实现

- 保留目录整理时的顺序、稳定项目 ID 和点击起点。引擎及书签保留原始媒体身份，只有后端收到解析后的不透明 loopback URL 队列。
- 每个网络队列单独拥有代理和按需读取器。注册列表 URL 不打开远程文件；任一时刻最多保留一个上游读取器。访问另一个文件先关闭前一个，再打开新文件；返回旧项重新打开。所有读取串行，释放等待进行中的操作及超时后才返回的原生句柄清理。
- 这是每队列一个上游读取器的约束，并非整个应用所有分析/播放读取器的全局数量证明。逻辑 URL 数等于列表项数；共享代理默认 8 源预算、16 客户端上限及 256 KiB 分块未全局提高。
- 同一列表必须来自同一已保存服务器，目录大小须为已知正整数；实际读取时再核对大小与可寻址能力。发生变化明确失败，要求刷新目录，不静默截断或增加替代播放路线。
- 网络队列经现有 Adaptive 层送给 System/MPV 契约；普通本地列表、单项路径、API26 门槛保持。没有新依赖、凭据来源、数据库迁移、应用层 EOF 重开循环或服务端修改。
- 复核发现原生打开超时后仍可能有迟到清理，本轮补齐真实 settlement 的等待与清理错误传播。取消异常也不能跳过 close；失败不清零。

## 未验证及已知风险

- 目录 B 超时未解决，不证明其由列表数量、编码能力、服务器或代理中的哪一项单独导致。20 项 H.264 通过也不能推广为任意列表/格式全部通过。
- 当前 x86_64 构建的 MPV 是 compile-only stub，并非可播放的 x86 MPV 库。原生 SMB 传输同样不可用；本轮没有真机 MPV/SMB 播放 PASS。换分支不会自动获得缺失的二进制能力。
- 所有网络读取串行且仅保留一个上游读取器，切换/预读频繁时可能影响吞吐；没有进行吞吐基准或长时间浸泡测试。
- 未测试目录内容中途变化、未知大小文件的真实服务器错误呈现、混合格式队列首项不受支持、音频听觉、随机模式、动态增删重排、HLS/DRM 或全部网络协议。未知/改变大小的失败及清理路径有主机测试覆盖。
- 字幕按用户要求留作 TODO；其他格式、ARM64 真机、资源计数与解码能力仍需独立矩阵。
- 原始布局、截图、网络目录和日志仅本机私有保存，未进入 Git；报告不意味着远程可重放私有原始媒体。未连接 SSH 或修改服务器内容。原 workspace 无本轮写入/构建/清理命令，未运行穷尽字节快照。
- 构建 checkout 的四个生成锁文件仍有未提交变化；本轮只提交明确源码、测试、计划和报告，不恢复或打包这些锁文件，不声称整个 checkout 干净。
