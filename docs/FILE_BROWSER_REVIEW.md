## 待讨论：文件夹和文件是否需要分开

用户反馈：个人使用时觉得分开太繁琐，但观察到许多产品也是分开的，因此仍在犹豫。尚未决定采用哪种方式。

用户已澄清：“分开太繁琐”主要指同一页里，文件夹与文件分成两块区域。本轮讨论聚焦该问题，不据此调整本地浏览模式切换。

检查时实现：两页都在单一滚动网格中先放文件夹、再放文件；网格模式下文件夹固定三列，文件按宽度两至四列。本地还提供目录浏览与平铺视频的模式切换。

讨论候选：

- 同一列表或网格，统一条目尺寸，文件夹置顶，用图标区分类别。
- 同一滚动区域，保留文件夹与文件的不同布局。
- 按名称等规则混排文件夹和文件。

用户选定方向：采用最简单的连续排列，显示方面文件夹与文件完全等同，不再补位；最多增加一个文件夹置顶选项。用户原文为“文件夹指定的选项”，暂按“文件夹置顶”理解。用户随后明确要求按不区分展示实施，本轮不新增置顶选项。

对应的展示方向：文件夹与文件使用相同列数、单元格占位和名称排版；用文件夹图标表达目录类型，点击仍进入目录。取消文件夹独立列跨度及补位，后续文件直接接在前一个条目之后。若增加“文件夹置顶”，仅改变排序，不另起一行；选项是否增加及默认值尚未确定。

评估以实际浏览负担为主：找文件是否需要额外切换、是否容易定位目录、是否浪费屏幕空间，以及从列表切换到网格是否保持清楚的顺序。

## 待讨论：本地添加与整理是否过于复杂

用户提出：本地同时存在虚拟、导入和新建文件夹，会不会过于繁琐。

源码核对：

- 自动扫描读取系统媒体库及相册；展示的是系统已有来源。
- “导入视频”通过系统文件选择器取得访问权限，保存原文件引用与当前虚拟目录的归属，不复制原文件。
- “新建虚拟文件夹”在数据库中建立应用内分组及父子关系，不创建真实文件系统目录。“虚拟”和“新建文件夹”属于同一整理机制。
- 导入和新建只在本地根层及虚拟目录提供；系统媒体库相册不提供这两项。真实和虚拟目录虽已统一展示，操作能力仍有差异。

初步建议：主流程聚焦自动发现和“添加视频”。应用内整理若保留，使用“分组”等能说明其含义的名称，并在创建时说明原文件位置不变；是否收起创建入口仍待用户决定。界面简化与移除数据库能力是不同范围，当前未删除任何入口、已有分组或数据。

用户进一步说明：添加虚拟管理主要是为了弥补鸿蒙环境下当前目录访问方式的限制；理想流程是直接扫描或添加已有文件夹，用户不必重新组织文件。但自行提供虚拟管理又增加了复杂度。

判断：当前项目采用系统媒体库查询和单文件选择授权。虚拟目录只组织已取得访问权限的文件引用，不能补足真实目录扫描能力；已有文件的组织与用户在应用内重新建立组织还可能形成双重维护。此判断基于当前项目实现，不将尚未接入的目录能力断言为所有鸿蒙版本均不支持。

后续简化候选：默认仅展示系统媒体库和用户添加的视频，手动添加结果直接可见；收起新建虚拟目录入口，保留已有虚拟目录与文件引用。内部授权、索引和播放进度仍有必要，但不必将“虚拟”作为用户需要理解的概念。是否实施尚未确定；未来若确认目标系统支持满足需求的目录授权，再接入已有真实目录。

用户新的参照与疑问：其目前观察到的鸿蒙播放器没有扫描入口，主要提供新建目录和用户导入文件；正在考虑向该模式靠拢。该观察来自用户，尚未调查具体产品，不能据此推断平台不支持媒体库扫描。

新增候选方向：导入优先。默认本地页展示用户主动添加的视频，“添加视频”为主入口，允许直接添加到根层；新建应用内目录是可选整理操作，不作为导入前置步骤。系统媒体库扫描是否降为次要入口或从默认流程收起，仍待决定。该方案与上面的扫描加导入方案是替代候选，尚未选定或实施；可复用已有授权、目录关系和文件引用存储，先调整产品入口与默认展示。

## 2026-10-02 文件夹信息简化规则（已确定，待实现）

用户要求先记录本轮规则，核对文件现有字段，并在后续实施时清理网络文件夹不再需要的统计逻辑。以下规则取代前面关于文件夹数量组合的建议；本轮只修改记录，不修改产品代码。

| 范围 | 确定的列表信息 |
| --- | --- |
| 本地文件夹 | 视频数量、总大小、日期；不再展示子文件夹数、全部文件数、图片数或字幕数 |
| 网络文件夹（非服务器列表） | 只显示日期；不显示数量、大小或“文件夹/空文件夹”类型标签 |
| 日期 | 统一显示年/月/日，沿用现有 `YYYY/MM/DD` 格式；不显示时分秒；保留完整原始时间戳供排序使用，不能先截断成日期或按显示字符串排序 |
| 网格 | 沿用已确定的无 chip 信息规则 |

网络文件夹的日期应直接使用当前目录列表返回条目的 `modifiedAt`，不为获取日期、数量或大小额外进入子目录。当前 `NetworkDirectoryBrowser.loadDirectory` 仅遍历已经返回的当前层结果、统计并缓存摘要，没有为子文件夹数量递归发起请求。后续删除文件夹数量标签、摘要查询及缓存；顶部当前目录数量/大小摘要是该统计的另一个消费者，须一并明确清理范围，不能只删除界面标签而留下无用计算。

清理注意：`NetworkDirectorySummaryCache.keyForServer` 同时被 WebDAV/SMB/SFTP/FTP/NFS 实际目录列表缓存调用。移除摘要缓存前应把必要的服务器目录缓存键移到已有合适位置，保留实际列表缓存、刷新及服务器配置变更隔离。同步删除失效的摘要标签函数和相关测试。

本地日期的待落实事项：`LocalMediaFolder` 当前没有日期字段，文件夹“按修改日期”排序也尚未比较时间戳；虚拟目录数据库有 `updated_at`，但批量统计更新会同时刷新多个目录的该值，不能直接当成各目录准确的内容修改时间。实施时需明确新建目录、扫描目录及“本地媒体”聚合入口的日期来源。视频数为零不代表目录为空；只有字幕或子文件夹时不得标成“空文件夹”。总大小是否包含所有文件、是否递归，以及缺失日期的展示方式尚未单独确定，不增加后台递归统计。

文件当前实际展示字段（未变更）：

- 本地列表：名称（扩展名可开关）、大小、视频清晰度、修改日期；字幕显示“字幕”，失效文件显示“文件不可用”并替代大小。视频时长位于预览内，播放进度位于预览底部，隐藏状态以标题旁图标表示。大小/清晰度/时长/日期分别受已有本地显示开关控制；当前清晰度和时长实际只用于视频。
- 网络文件列表：名称、大小、存在有效时间戳时的修改日期；准备播放时临时显示“正在准备播放…”。当前没有展示清晰度或时长，也未接入本地信息字段开关。
- 两侧网格：名称、预览和操作/状态标记，不展示大小、日期等 chip；本地视频保留播放进度。
