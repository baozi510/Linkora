# Playback Phase 8B — Real-arm64 Media Capability Matrix

> Scope: functional codec/container/audio compatibility on Mate60.
>
> UI polish, fullscreen layout, display-mode selector, performance ranking and Auto tuning are out of scope.

## Goal

Use the permanent `test-lab/media-compatibility/cases.json` corpus to measure System and MPV playback capability independently.

This phase answers:

- Can System open and functionally play this fixture?
- Can MPV open and functionally play this fixture?
- For Tier A, is there at least one usable product backend?
- Does any fixture expose crash/ANR/hang/release/session-isolation defects?

It does not answer which backend is faster or should be Auto default.

## Corpus

The seed matrix contains 59 cases:

- 56 file fixtures;
- 3 streaming manifests;
- video/container combinations;
- audio-only formats;
- one embedded-SRT fixture;
- mainstream, legacy and rare formats.

Fixtures are generated by `generate-samples.ps1`, except the checksum-pinned APE sample.

Before runtime, produce a sanitized fixture manifest containing at least:

- case ID;
- file size;
- SHA-256 for file fixtures;
- generated/fetched provenance;
- ffprobe container/stream truth where available.

Do not commit generated media binaries.

## Backend execution

Every case must be executed separately in:

- forced System;
- forced MPV.

Do not infer one backend from the other.

Do not use Auto for the 59-case matrix.

### Video PASS

Minimum functional PASS:

- prepare/open succeeds within the bounded case timeout;
- PLAYING state is reached;
- first real frame is observed;
- playback position advances after first frame;
- short pause/resume is functional when safely automatable;
- leave/release completes cleanly.

The 3-second synthetic fixture does not require full long-form seek validation.

### Audio PASS

Minimum functional PASS:

- prepare/open succeeds;
- PLAYING state is reached;
- playback position advances for at least ~800 ms;
- app audio renderer evidence may be used as objective support;
- leave/release completes cleanly.

Do not claim subjective audible output unless a human explicitly verifies it.

### Stream PASS

Minimum functional PASS:

- manifest opens;
- PLAYING;
- first frame;
- position advances;
- leave/release cleanly.

## Verdicts

Per case/backend use exactly:

- PASS
- UNSUPPORTED
- FAIL
- TIMEOUT
- NOT_RUN

UNSUPPORTED is a valid backend capability result, not an infrastructure failure.

## Tier gates

Tier A:

- each case is a product capability gate;
- System may be UNSUPPORTED if MPV PASSes;
- MPV may be UNSUPPORTED if System PASSes;
- both non-PASS => Tier A product-gap finding.

Tier B:

- compatibility target, but individual unsupported formats are non-blocking;
- investigate unexpected failures.

Tier C:

- observational;
- success is desirable but not required.

All tiers:

- crash;
- ANR;
- unbounded wait/retry;
- stale-session event pollution;
- inability to leave/release;
- resource accumulation

are failures independent of format tier.

## Timeouts

Use a bounded per-case open/prepare timeout, default 12 seconds unless the existing backend contract has an earlier terminal error.

Do not repeatedly retry a failed fixture to force a PASS.

One controlled rerun is allowed only for clear external test-environment interruption and must be recorded.

## Evidence schema

Write one NDJSON row per case/backend.

Required fields:

```json
{
  "caseId": "mp4-h264-aac",
  "backend": "system",
  "verdict": "PASS",
  "prepareObserved": true,
  "playingObserved": true,
  "firstFrameObserved": true,
  "positionAdvanced": true,
  "audioRendererObserved": null,
  "errorCode": null,
  "errorClass": null,
  "releaseClean": true,
  "crash": false,
  "anr": false,
  "unbounded": false,
  "notes": ""
}
```

Use null where a field is genuinely unavailable.

Do not fabricate first-frame evidence for audio-only media.

## Summarizer

After collection run:

```powershell
node scripts/summarize-playback-capability.cjs <raw.ndjson>
```

Expected complete matrix:

```text
59 cases × 2 backends = 118 records
```

No duplicate case/backend rows.

## Display modes

Playback display modes are a separate backend capability:

- FIT_CONTAIN;
- FILL_CROP;
- STRETCH;
- ORIGINAL where truly supported.

Do not implement or test their UI selector in Phase 8B.

Do not use fullscreen layout appearance as codec/container PASS criteria.

## Analyzer sharing

This is the same permanent corpus that later feeds Analyzer capability.

Do not infer Analyzer PASS from Playback PASS.

If analyzer observations are collected incidentally, keep them in separate fields/artifacts and do not reopen accepted Analysis policy.

## Out of scope

- Auto selector tuning;
- performance ranking;
- HDR/Dolby Vision output correctness;
- DTS-HD/TrueHD/Atmos/DTS:X passthrough semantics;
- subtitle visual rendering quality beyond basic media-open behavior;
- power/thermal;
- fullscreen/UI polish;
- Direct I/O;
- thumbnail research.

Advanced semantics remain for later dedicated validation.
